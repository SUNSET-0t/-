# v0.2.1 手机按钮与未安装服务状态修复

用户截图与录屏显示“打开接口设置”“刷新服务状态”“添加渠道”都被挤成单字竖排，网页能打开但服务状态是未安装/未启用。

## 已复现的布局原因
SillyTavern release 的 public/style.css 中 `.menu_button` 使用 `width:min-content`。新增渠道界面的普通文本按钮没有覆盖这个宽度，中文最小内容宽度退化为一个字。此前测试宿主没有载入该规则，因而漏测。

在本地 Chromium 393px 宽视口中，加入这条宿主规则后复现：刷新按钮宽约41px、高108px；补丁后宽约108px、高44px。具体字体导致尺寸有差异，不作为用户设备保证。

## 修复范围
- 只对本插件的渠道/通用页面按钮覆盖宽度、换行与横向排版；不修改其它酒馆扩展的 `.menu_button`。
- 窄屏操作组允许整行排列，密钥输入与显示按钮不互相挤压。
- 标签页导航使用面板内原生事件委托，与后端连接状态分离。未安装服务时仍能切页，不能因为后端失败而卡在设置页。
- 未安装服务时显示独立安装说明，禁用添加渠道的原因清晰可见。404只能说明当前页面未找到独立服务端点，不证明未安装是唯一原因。
- 使用 release-0.2.1.js 版本化入口并更新变更资源的版本参数；仍需正常刷新页面，不承诺能够绕过所有浏览器/代理缓存。

## 未改变
本补丁不安装服务器插件，不修改 config.yaml，不读取/写入正文密钥，不调用生成模型，不启用自动重Roll。服务端协议仍为1，服务版本仍可为0.2.0；这是网页端布局补丁。

配套服务需要在运行酒馆的电脑完成一次安装/启用并重启。已经完成仍显示404时检查服务端启动日志，不让用户反复清缓存或重复clone。

## 回归测试
真实Chromium使用仓库模块、原生样式中的 min-content 按钮规则、手机触屏及桌面。覆盖服务在线、404、标签页来回切换、关闭重开、按钮文本尺寸与水平溢出。服务商网络为模拟响应，测试不花费真实模型额度。
