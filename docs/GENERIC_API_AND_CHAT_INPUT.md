# 下一阶段：独立 API、阶段模型与通用聊天输入

状态：依据用户当前反馈确认的功能要求与实施约束；本文不是功能已发布的说明。当前 R2-B 固定样本不能代表通用人物系统。

## 1. 用户要求

- 插件自己的界面中直接配置独立 API 地址、密钥和模型，不强制先去酒馆 Connection Profiles 创建辅助配置。
- 允许不同任务阶段使用不同模型；模型列表来自相应 API 接口实际返回的可用模型，不硬编码某几个 Gemini 版本。
- 默认处理当前正在游玩的聊天、角色卡及相关世界书资料，不显示固定作品、人物姓名、1月16日之类的剧情坐标。
- 插件自动整理人物与资料、生成 ID 对应关系。用户不需要为每个新档手写 JSON 或人物映射。
- 已有特定作品测试案例仅保留在主动打开的开发测试区，不能自动进入真实聊天。

## 2. 独立连接

每个连接包含：连接名称、协议类型、Base URL、密钥状态、模型列表及获取时间、超时、请求限额。UI 提供保存连接、获取模型列表、明确标注的生成测试按钮。

优先落地自定义 OpenAI-compatible 接口；原生 Gemini 等协议必须有单独适配，不得把所有接口都按同一 URL/字段调用，也不得用网页宣传名冒充可调用 model ID。原来的 Connection Profiles 可保留为可选兼容来源，不再是唯一入口。

配置或运行插件不得修改正文连接的地址、密钥、模型、预设或全局选中状态。失败时禁止悄悄回退到正文接口或昂贵模型。

密钥不得存入聊天、世界书、导出配置、日志或公开仓库；不要求用户把密钥发到聊天里。采用隔离的服务端密钥存储/调用方案并验证兼容性。注意：酒馆部分密钥写入接口会改变同类密钥的 active 状态，不能把共用密钥槽直接当作插件专用存储。验证不足时明确限制，不以静默覆盖主密钥或明文普通设置存储替代。

更换接口或凭据后刷新/失效原模型列表；每个阶段选择都绑定连接 ID 与确切 model ID。模型列表获取不触发正文生成，实际小额生成连通测试需明确显示其会消耗辅助模型额度。

列表获取失败时显示真实错误，不填充一份看起来成功的推荐列表。允许手动输入 model ID，但标记未验证。列表中的模型也未必都支持所需生成协议或 JSON 输出，不能以列出即证明支持。

## 3. 阶段模型配置

模型槽位：

| 阶段 | 用途 | 默认调用安排 |
| --- | --- | --- |
| 初始资料整理 | 提取相关人物、经历、知情范围 | 首次启用或资料明显缺失时；通常合并到同次人物判断 |
| 常规人物判断 | 立场、意向、普通重要互动 | 按需一次 |
| 复杂人物判断 | 多人物冲突、重大承诺与代价 | 根据已知信号直接路由；不默认先调用轻量再调用强模型 |
| 累积变化检查 | 整理多轮细微互动 | 合并进下一次必要判断，独立定时调用由用户另行开启 |

允许所有阶段共用一个模型，也允许分别选择同一接口或不同连接。阶段不等于固定流水线，不能因此每轮自动串联三四个请求。

推荐只能从当前接口提供的模型中筛选并标明候选性质。模型名不能证明价格或能力；价格未知显示未知，用户可填写服务商计价。不能将服务商中转别名的价格当作官方价。

费用底线：默认主模型只正常生成一次；不自动重 Roll；不默认生成后调用审核模型。辅助调用前显示此次预计的生成请求次数和输入范围。用户切换多调用模式时明确增加的成本。

## 4. 当前聊天作为默认资料来源

资料源包括当前选择的聊天分支/回复候选、相关角色卡字段、相关世界书设定、此前已确认且仍有效的插件状态、当前尚未实施的用户输入。

第一步为本地程序筛选和分块，不调用模型：
- 读取原始聊天消息，而非依赖屏幕显示的 HTML 或正则渲染结果；仅取当前分支和被选中的回复候选。
- 对已识别的结构区分实际正文、平行线事件、人物内心、摘要、状态栏与剧情规划。
- 对无标签的普通文本提供退路，不要求必须使用某个预设或咩咩特定标签。
- 排除可识别的 lore_search、story_driver、acg_think、combat_driver、parallel_line_drive 等规划/推理段，不把未来计划当已发生剧情。
- story_scene 内嵌的规划仍需排除；parallel_line 的发生地点与见证范围分开保存，不能让不在场人物自动获知。
- memory_log 是来源模型给出的摘要，并非独立校验后的事实；npc_log 是私人心理候选，不成为全员共享知识。
- 数值与明确对话可记录来源；抽取成功不等于已经验证其人物合理性。
- 为来源分配消息/候选标识与证据编号，标记截断、缺失、未知，展示本次实际读取范围。

第二步为辅助模型在一次请求中完成必要的语义整理与本轮判断：
- 识别参与人物、相互关系、当前目标、具体可知信息。
- 未提供的原创人物经历/秘密保持未知，不能为了档案完整虚构背景。
- 分离事实、人物解释、行动意向、行动与结果。
- 玩家未执行的输入仅作为行动意图，不直接变为 NPC 已看到的事件。
- 根据已有具体事件使用 decision；未来细节尚未发生时使用 stance，不提前补造礼物或整场剧情。
- 输出证据编号、关键未知与人物行动摘要，不输出逐镜头剧本或长篇内心独白。

相关世界书不能省略，也不能把整本数万 token 不加筛选地反复发送。具体条目读取/激活路径必须结合酒馆接口版本验证；无法获得时展示缺少来源，不能宣称已完整读取。

## 5. 人物映射与信息边界

默认从当前来源中建立稳定的实体 ID 与真实姓名/别名映射；玩家实体由当前 persona 与聊天上下文识别，不硬编码任何角色。

同名或别名歧义时提供候选供用户确认，不悄悄合并角色。无名人物可有临时实体 ID，不自动为其虚构姓名或完整生平。

通用提示词不含作品名称、时代、恋爱结局或测试期待。正常 UI 可显示当前档真实出现的人物，但不能固定显示示例人物。手工映射仅作为高级纠错工具，普通使用不必编辑。

对多人物批量判断，分别限定各自依据；模型批量看到材料并不保证秘密隔离，敏感场景的视角隔离需单独验证。不要宣传完全盲判或保证零泄漏。

## 6. 默认流程与界面

配置独立接口 → 获取其模型列表 → 为阶段选择模型 → 读取当前聊天并预览范围/人物 → 必要时一次辅助判断 → 注入当前分支的下一次正常正文 → 本地保存已发生内容/待核对内容。

正常首页：当前聊天、资料范围、已识别人物、独立接口连接状态、当前任务模型、预计辅助请求次数。首次没有人物时显示未读取，不能用固定样本填充。

设置：连接管理、阶段模型、调用模式、输入范围与预算。

高级：来源详情、原始 JSON、人物映射纠错、明确隔离的测试样本。

一个自定义样本的结果不得因为切换了聊天就能直接注入；真实聊天的结果必须绑定聊天/候选/输入版本，过期或换档时失效。不得将开发测试源伪装成当前档来源。

## 7. 实施顺序与验收

先验证独立接口、密钥隔离与动态模型选择，再接入真实聊天资料、自动人物映射和合并抽取/判断，最后启用自动生成前拦截。阶段实施不应再次以硬编码剧情填补缺失功能。

必须测试：
1. 保存和调用插件接口后，正文配置与主密钥没有改变；日志/导出不含密钥；缺失配置明确报错且不回退。
2. 模型选择仅来自当前连接，模型列表失败及切换连接不沿用错误列表；手动 ID 明确标记。
3. 在全新无关题材聊天中不出现内置测试作品、人物、日期；没有角色资料时显示未知。
4. 同一个短指令可以从当前聊天提取材料并判断；正常使用无需手填 JSON。
5. 规划不混入已发生事件；人物不自动知道离场事件或他人心理；摘要不能覆盖明确矛盾。
6. 截断和资料缺失可见；新分支、重 roll、编辑输入后不复用过期决策。
7. 打开面板/读取本地资料零模型调用；常规一次必要判断最多一次辅助生成；正文仍只运行一次；无自动审核重 roll。
8. UI 使用既有原生折叠设置和已验证的原生弹窗/栏内模式，保留手机兼容测试。
