# v0.3.1-r2b 简单设置与 API Key 输入

## 用户反馈
v0.3.0 保存 Key 会触发 Android Chrome 的“保存密码”提示，默认显示四个阶段配置和渠道列表对新手过于复杂。

## 本次改动
- 默认只有一个辅助接口与一个模型；点击“保存并统一使用”把四个任务引用设置为同一个渠道/模型，不产生四次生成。
- 已保存的渠道、密钥引用、模型列表、分阶段配置沿用原存储。打开新版不执行迁移、删改或自动统一；已有不同阶段配置时要用户明确确认才替换。
- 所有阶段分工收进默认折叠的“高级设置（可以不动）”，渠道列表收进“管理已保存接口”；新增/编辑时暂时只显示当前接口编辑区。
- 新接口通常只需选择服务商并填写 Key。官方地址只读且折叠，自定义地址显示输入；名称和请求参数也折叠。原来的原生调用与 Key 保存代码不改。
- 原 `<form>` + `type=password` + `autocomplete=new-password` 容易被当作账号密码。新版使用普通设置区和非登录 token 字段，在支持 `-webkit-text-security` 的浏览器中用普通文本框加视觉遮罩；没有密码/新密码自动填充标记，按钮均为 type=button。
- 不支持 CSS 遮罩时退回密码框保护屏幕内容，并说明仍可能触发浏览器提示。遮罩只防旁观者读屏，不是加密或脚本隔离。不会要求用户关闭 Chrome 全局密码管理，也不操作用户 Google 密码库。
- Key 保存后、关闭编辑、关闭原生弹窗/栏内模式与 pagehide 时清空未提交文本；已保存的原生 Key 不会因此删除。

## 解释四阶段
资料整理：整理人物与经历；常规判断：处理一般重要互动；复杂判断：处理多方/高代价选择；累积检查：观察多轮变化。这些是后续内部任务分工，不要求用户准备四个模型，不是当前已经启用的四段调用流水线。

## 验证边界
结构测试检查没有登录表单、没有 new-password、支持遮罩时不使用 password 类型，视觉遮罩/显示/清空正确；手机和桌面浏览器检查简单配置、旧配置保留、高级修改与明确统一确认、默认折叠、模型列表和零隐式生成。

无头 Chromium 不包含用户登录的 Google 密码管理器或 Android 原生弹层，因此**不能把这些测试通过宣称为所有 Chrome 版本绝不会再弹保存提示**。用户设备仍需最终确认。

当前仍是连接测试阶段。没有新增当前聊天抽取/人物判断自动化，不改变咩咩预设/角色卡/世界书，不调用昂贵正文、不安装任何配套服务。
