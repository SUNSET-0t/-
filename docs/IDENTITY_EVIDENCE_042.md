# 0.4.2-r2b：身份出处与行为依据分开校验

## 当前反馈能证明什么

用户截图的错误为“人物姓名没有出现在其引用的证据中，未注入”。这是0.4.0/0.4.1本地validateDecision的分支，不是输出长度或账户余额错误。代码到达这一步表示已拿到可解析响应并开始人物校验，但不表示全部语义已通过。

截图没有给出具体人物姓名、返回JSON与sources原文，无法确定真实案例是代称、名字格式、漏引身份条目、材料被截掉还是模型编造人物。本补丁复现并修正可确认的规则缺陷，不宣称已复现用户的完整输出。

## 原问题

旧规则要求name必须字面出现在同一个evidence引用集合中。比如角色卡C0有姓名，正文H0_0使用“她”，模型合理引用H0_0解释行为却未重复引用C0，整轮会被拒绝。这混淆了“这个称呼来自哪里”与“立场以哪段经历为依据”。

## 修改

新增identity_evidence与原evidence并存。提示词要求名字照抄原材料，身份引用和行为引用可以不同；本地校验也兼容旧输出没有identity_evidence的情况，在同一请求已发送的有限sources中查找名字出处。仅补 identity_evidence，不改变模型原来的行为evidence，不重新调用模型、不推定代词究竟指向谁。

Unicode NFKC、前后空格、汉字之间空格和明确显示引号/Markdown包装可规范化。没有同音、简繁、全名补全、翻译或别名猜测，也不删除括号里的另一身份。字面存在只证明名称有来源，不证明是场中唯一此名人物，更不证明其内心判断正确。

当前玩家意图、过去指令、玩家设定和计划段不能单独建立NPC身份。角色设定/已读叙述/其他分类型记录可以提供名字字面出处，但不因此变成共同知识或已发生的事实。未读聊天/被截掉的内容/未选swipe不会被临时追加到验证材料。

真实不存在的人名、无效证据ID、未匹配别名、玩家本人、重复人物仍暂停；不静默保留一部分人物然后开始昂贵正文。错误现在包含具体未匹配姓名、相关引用编号；进阶诊断保留有限结构信息，不保留原始响应、思考原文或Key。

## 使用

更新后正常发送即可，API/模型和预算策略沿用0.4.1。不需要用户填姓名表、改世界书或加一次修复API。记录页区分身份出处与行为依据，进阶可看本地匹配记录。真正无法确认仍暂停并说明人物，不能承诺所有输入都不再报错。

## 测试

单元测试覆盖姓名在卡/行为用代词、分开身份引用、旧输出兼容、格式差异、无来源姓名、无效ID、只在意图出现、重复/玩家姓名、单字误匹配、英文子串与未支持别名。流水线检查一次辅助后一次正文、不改聊天、无来源失败时零正文且保留输出用量；缓存和跨档失效保留。

手机320/393像素及桌面使用固定酒馆hook与提示词收集器、模拟提供商。测试不调用真实模型、未获得用户完整原始材料，不把模拟通过宣传成已验证真实NPC拟真效果。

参考： https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/normalize 。NFKC处理兼容形式，不是自然语言实体消歧工具。
