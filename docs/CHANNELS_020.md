# v0.2.0 独立渠道配置阶段

## 实际范围
实现插件内渠道编辑、固定官方地址、独立密钥保存、模型列表读取、阶段模型选择和短生成连通测试。**当前聊天自动取材、自动人物映射与新渠道到人物判断的接线尚未启用。**旧固定样本只保留在主动展开的旧实验回归区，默认不填充人物资料。

## 为什么需要一次服务端安装
网页扩展运行在浏览器。为避免把 Key 放进普通设置或覆盖正文同类密钥槽，增加一个独立服务端模块。它按当前登录用户的目录存储资料，不读取正文 secrets.json。

本版本不会自动修改 config.yaml，也不会自动开启服务器插件。服务未启用时面板只显示说明，不接收或暂存密钥，不回退正文 API。

## 一次安装（在运行酒馆的电脑上）
1. 停止酒馆并备份 config.yaml。在酒馆根目录的终端执行：

```text
git clone https://github.com/SUNSET-0t/- plugins/npc-independent-api
```

2. 手工检查 `plugins` 文件夹，只保留信任的服务器插件。然后在 config.yaml 将 `enableServerPlugins` 改为 `true`。这会启用该目录下所有符合要求的服务器插件，不只本插件。
3. 启动酒馆。服务端按照本仓库 package.json 的 main 加载 server/index.mjs；网页端仍通过酒馆扩展管理正常安装/更新同一仓库。
4. 手机刷新页面，在接口设置点击刷新服务状态，应看到“独立服务 0.2.0 已连接”。

安装后不用手动上传任何文件。网页扩展通过原有更新按钮更新；服务器副本按酒馆服务器插件自动更新设置，在重启时检查更新。若关闭了该自动更新选项，可在酒馆根目录运行 `git -C plugins/npc-independent-api pull --ff-only`，再重启。网页刷新不能替代服务器重启。

用户使用的是 Windows；命令在电脑终端执行，不在手机浏览器输入。安装目录不确定时先确认实际目录，不能猜测后直接执行。

## 设置与测试
选择提供商 → 填独立密钥 → 保存 → 获取模型列表 → 选择默认模型 → 保存。各阶段可以选择相同或不同渠道/模型；它们不是自动串联请求流程。

保存、刷新服务和读取设置不会调用模型。模型列表请求只访问提供商列表端点。“测试生成（可能收费）”必须确认，只发送固定文本 `Reply with OK only.`，可见输出预算64（不同厂商对思考费用的定义不同）。不发送游戏上下文，不自动重试，不产生正文或重Roll。模型只返回思考而无可见输出时会报错，仍可能已经计费，应查看服务商账单。

本版 OpenAI、Google AI Studio、Claude、DeepSeek、OpenRouter 和自定义 OpenAI-compatible 已有列表与生成适配。硅基/火山预设支持明确手填模型调用，列表适配未完成时明确报错，不伪造列表。Vertex 项目认证暂未实现且在界面禁用。流式、私网/本机 API 转发暂不开放。

## 密钥与网络边界
服务端独立目录为当前用户根目录下 `npc-independent-api/`。channels.json 的密钥部分用 AES-256-GCM 加密，vault.key 保存解密材料；两个文件必须一并保护，服务器管理员仍可解密，不能宣称能抵御本机管理员。它们不在公开仓库、不写入游戏或浏览器普通设置。界面不回读已保存的完整密钥，显示按钮仅作用于当前新输入。

官方 URL 在服务端再次验证，不允许被导入配置覆盖。更换地址/提供商必须重新输入密钥，不能将旧 Key 发往新地址。出站仅允许 HTTPS443 公网IPv4，DNS解析与实际连接绑定；拒绝内网、回环、链路本地、保留地址与重定向；限制请求/响应大小与超时，不开放跨域访问。

安全仍依赖酒馆本身的登录/访问控制。不要把未认证的酒馆直接暴露公网。手机到酒馆的链路也需要保护：公网HTTP拒绝输入密钥，局域网HTTP需确认可信网络，优先使用HTTPS。

## 测试与限制
单元测试使用虚构凭据及模拟响应，检查存储隔离、密钥加密、配置修改冲突、切换地址强制重新认证、分页、防私网请求和零隐式生成。浏览器测试覆盖渠道编辑与模型选择。自动测试不调用收费模型；实际服务商权限、余额和用户酒馆兼容性仍需用户自选渠道做一次小额测试。
