# NPC 人物自主模拟 · 自动运行版 v0.4.0-r2b

**配置一个辅助 API 和模型，保存后照常聊天即可。**无需手动运行判官、编辑人物JSON、点击注入，也不需要额外服务器模块或电脑命令。

已有0.3.x接口、密钥引用与模型分工继续沿用。只更新网页扩展并刷新页面，顶部应显示0.4.0-r2b。仓库地址不变：`https://github.com/SUNSET-0t/-`。

## 正常操作

第一次：API设置 → 配置辅助接口 → 填Key并保存 → 获取模型列表 → 选一个模型 → 保存并统一使用。

已有配置：直接回原聊天发送平常的短指令。插件默认启用，根据当前选中的剧情与人物材料，先形成NPC立场摘要，再自动放入同一轮正文请求。无需打开面板再执行。主模型仍使用原来的预设、角色卡、世界书和正文接口。

用户消息旁显示“NPC · 人物判断中 / 已注入本轮 / 已参与本轮 / 本轮跳过 / 正文前暂停”。“已参与”只有收到最终请求事件且找到实际摘要标记后才显示；仅设置了注入但未获得确认会明确区别。

面板“运行”看当前状态，“记录”看本轮人物与证据，“进阶”看实际注入/资料范围。正常游玩无需打开这些页。

## 自动流程

本地读取当前选中聊天、角色卡和相关世界书 → 本地筛选 → 一次辅助生成同时整理人物和判断立场 → 格式与证据ID检查 → 临时注入本轮正文 → 正文正常生成一次 → 清理临时注入。

插件不做生成后模型审核，不自动重新生成正文，不把四阶段串成四个请求。默认把资料整理合并到本轮判断；有高级分工时，明确时间推进优先使用review，重大冲突关键词优先complex，其余regular，缺少对应配置则使用用户已指定的regular。不会改用正文模型补位。

默认“自动按需”是保守的本地筛选：只跳过明确的背包/状态/余额查看等命令，不把日常互动和含糊的“继续”误当不重要。因此大多数剧情回合会增加一次辅助生成。相同输入、相关资料、模型配置的重生成可复用本页面内已通过格式检查的结果，不再次调用辅助模型；这不禁止用户主动重新生成正文，也不承诺服务商内部只计费一次。

## 出错怎么办

辅助超时、失效密钥、无效JSON、引用不存在的证据等情况，会调用酒馆中止回调，在昂贵正文发送前暂停，并显示原因。插件不自动重试、不静默换模型。

可以修正辅助API后再发送，或者在运行页明确选择“仅下一轮跳过辅助判断”。跳过后本轮恢复原正文流程，不代表NPC判断成功。暂停/恢复开关在运行页；保存API和模型后不需要另行开启。

停止生成、切换聊天、修改消息或回复候选会使未完成结果失效。辅助请求发出后取消，远端仍可能计费，无法保证退款。

## 读取范围与真实限制

本版默认从当前分支最近8条历史消息、当前待执行输入、角色卡和相关世界书条目构造材料；设定/历史文字预算约18000字符，不是18000token。最多12本关联书参与读取，最多10条相关世界书进入候选、最多4位人物进入摘要。超出范围会截取并在诊断中提示。

世界书直接读取选择/关联的书，不第二次运行主模型的激活/递归/冷却扫描。这里只做相关性检索，不宣称完全等同主模型最终激活列表；复杂次要条件、角色过滤、概率及冷却等未适配条目保守跳过并显示警告。缺失的书无法凭空补全。

识别并排除已知lore_search/story_driver/acg_think/combat_driver等规划段。私人内心、离场事件、摘要、数值声明与可观察叙述分开标记；无标签的普通文本也支持。来源区分不保证模型永远不会读心或曲解，模型语义仍需实际观察。

**这不是完整长期记忆插件。**尚没有持久化的多年人物账本或全本世界书向量召回；超过读取窗口的重要经历可能缺失。摘要/意向不自动写进聊天或当作已发生事实，不修改好感值、角色卡、世界书、咩咩预设。重新刷新页面会清空本页面的临时决策缓存和运行记录，不删除原聊天。

自动调用与同轮注入机制可测试，但不能保证所有模型和题材都已达到拟真效果。目标是人物自身动机，不以必须拒绝、吃醋、降好感为成功指标。

## 接口与密钥

沿用0.3.x的原生调用：Key保存酒馆密钥库，普通设置只含引用；不调用完整Key回读，不写游戏或日志。新增Key后的默认项恢复是多步过程，不是服务器原子事务；保存时不要在别的窗口同时切换Key。旧服务器副本不再参与。

后台只调用所选辅助API。OpenAI、Google AI Studio、OpenRouter、硅基、DeepSeek/自定义等按已有渠道适配；Claude/火山仍可手填模型；Vertex认证未接入。提供商实际能力和价格以接口为准，不内置永久型号或虚构价格。

## 验证与兼容边界

测试使用真实扩展模块、固定上游SillyTavern的runGenerationInterceptors/setExtensionPrompt/getExtensionPrompt及原生密钥代码。浏览器宿主其余部分、服务商和正文模型响应是模拟的，所有Key均为假数据，不产生真实模型费用。

覆盖：不用打开插件的正常发送、一次辅助→一次正文、最终请求确实带有注入、保留原预设、JSON失败不发正文、同输入重生成缓存、切换聊天取消、原生密钥与简单配置回归、320/393px手机和桌面。

尚不能宣称与所有第三方扩展并发、所有酒馆旧版本以及全部代理/模型已实测兼容。复杂宿主可能在生成途中重建提示词；记录会区分“已设置”和“已确认进入请求”，不能只看是否有按钮或HTTP成功。
